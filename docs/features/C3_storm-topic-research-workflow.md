# C3: STORM topic-research workflow

## Goal
**Destination.** An operator provides a topic; a repo-local `spur workflow` writes a D4 STORM `Content` report (markdown + outline + citations + provenance) by composing a new Firecrawl-backed web-search ingestion plugin with the existing `content-gen` generator — no publish step, and no live web retrieval inside D4.
## Scope
- In:
  - A new `kind: ingestion` plugin under `plugins/ingestions/web-search/` (Firecrawl is the v1 HTTP backend, not the plugin name).
  - Topic → `Doc[]` via query expansion + Firecrawl search/scrape; secrets only via env (C1 §1.3).
  - `--in` is a JSON config file (C1 §2.2 API source), at least `{ "topic": "..." }`.
  - Linear state-machine workflow at `.spur/workflows/kk-storm-research.yaml` (temporary home; `~/.config/kk/` is later).
  - Reuse `content-gen` unchanged; the “analysis report” is D4 `Content`.
  - Operator input is a topic string (workflow `--vars`), which the workflow materializes as the ingest `--in` JSON.
- Out:
  - Publish plugins / channels.
  - Changing D4 internals or putting retrieval inside `content-gen`.
  - Stanford interview loop or Co-STORM in v1.
  - A second “analysis-report” generator plugin.
  - Implementing the `Brief` schema in `@gobing-ai/kk-core`.
  - Migrating the YAML to `~/.config/kk/`.
  - A `kk` sugar command for the workflow.
  - Python / DSPy / `vendors/storm` at runtime.
  - Feature **I** (LLM wiki).

### Decisions so far

- Compose plugins — retrieval lives in ingestion; D4 stays grounded on `Doc[]` (discovery, 2026-08-13).
- One ingest plugin; workflow is linear topic → ingest → generate (discovery, 2026-08-13).
- Reuse `content-gen`; the analysis report is D4 `Content` (discovery, 2026-08-13).
- v1 terminal artifact is the Content file; no publish (discovery, 2026-08-13).
- Plugin id/path is `plugins/ingestions/web-search/`; Firecrawl is the intended live backend (discovery, 2026-08-13).
- `--in` JSON: required `topic`; optional `maxResults` (default 8) and `fixture` ([0054](../tasks/0054_specify-the-firecrawl-topic-to-doc-ingest-contract.md)).
- Env for the future live path: `FIRECRAWL_API_KEY` → `Authorization: Bearer` ([0054](../tasks/0054_specify-the-firecrawl-topic-to-doc-ingest-contract.md)).
- Preferred live call: `POST https://api.firecrawl.dev/v2/search` + `scrapeOptions.formats: ["markdown"]`; v1 query = the topic string ([0054](../tasks/0054_specify-the-firecrawl-topic-to-doc-ingest-contract.md)).
- Fail-loud: zero hits → `[]`+exit 0 (C1); hits-but-no-bodies → exit 1; live path without `fixture: true` → exit 1 until a live client ships ([0054](../tasks/0054_specify-the-firecrawl-topic-to-doc-ingest-contract.md), [0055](../tasks/0055_prototype-the-storm-research-workflow-dry-run.md)).
- Workflow: state-machine `prepare → ingest → generate → done|failed`; success edges `always` so `--dry-run` reaches `done` ([0055](../tasks/0055_prototype-the-storm-research-workflow-dry-run.md)).
- Shipped v1 is the fixture path (`fixture: true`). Live Firecrawl client is **not** in 0054/0055.
