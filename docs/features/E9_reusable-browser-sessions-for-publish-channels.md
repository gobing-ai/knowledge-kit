# E9: Reusable browser sessions for publish channels

## Goal

Publish channels can reuse an authenticated browser profile through a shared, cross-project browser automation package, with XHS as the first proven consumer.

## Scope

**In scope**

- A reusable ts-libs browser-session package specified in an upstream Spur task, supporting user-driven headed login, a caller-selected persistent profile, and later headless page automation.
- Knowledge-kit XHS image-post publisher uses the package through its existing browser launch seam and keeps its current profile location and observed publish results.
- Offline regression coverage and a read-only headless profile reuse check; clear behavior when a site rejects or expires the session.

**Out of scope**

- New browser implementations for X, Substack, Juejin, InfoQ, or Medium; the current Medium publisher uses an API.
- Moving XHS selectors, uploads, closed-shadow CDP commands, or draft/public semantics into the shared package.
- Changing the XHS publish default to headless, exporting credentials, or adding password storage.
- Publishing the new package to npm or making a public XHS post as part of planning.

```gherkin
    # covers: I3, I4, I5, I8
    Given the operator has completed a headed login to a dedicated XHS profile
    When a later process performs a headless read-only check using that profile
    Then it reports authenticated readiness only if the XHS-owned predicate passes, otherwise a clear failure
```
