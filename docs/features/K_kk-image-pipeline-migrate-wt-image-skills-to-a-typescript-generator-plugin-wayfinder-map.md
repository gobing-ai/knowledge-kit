# K: kk image pipeline — migrate wt image skills to a TypeScript generator plugin (wayfinder map)

## Goal

Ship `plugins/generations/image-gen/` — a TypeScript `kind: generator` plugin with a full provider matrix and orthogonal `format × style` presets — plus the `plugins/kk` skills and slash command that drive it, replacing the four Python-based `wt` image capabilities and verified shippable (`/sp:dev-verifyall --feature K` → Shippable: PASS).

### Open questions

- **Preferences home** — baoyu blocks on an `EXTEND.md` preferences file (project → XDG → home) carrying default style/format/provider. kk already has `~/.config/kk/config.yaml` with `plugins.generations.<name>.env`, which is secrets-shaped, not preference-shaped. Reuse kk config, add a sibling preferences file, or both? Blocks the skill UX ticket (agent surface) and the plugin's option-resolution order.
- **Confirmation policy in non-interactive runs** — baoyu requires operator confirmation before every generation (real money per image). A `spur workflow` node has no operator. Does the plugin need an explicit auto-confirm/budget-cap mode, and what is the default? Blocks the plugin IO ticket.
- **Vendor vs reimplement the 12 adapters** — baoyu-skills is MIT, so porting is legal with attribution. Carrying 12 foreign adapters + their dialect quirks into `plugins/generations/image-gen/src/providers/` is a real maintenance and attribution commitment. Port verbatim-with-attribution, or reimplement against a kk-owned interface? Blocks the provider ticket's shape (not its inventory work).

### Decisions so far

- **Engine home = generator plugin.** `plugins/generations/image-gen/` with `kind: generator`; `Doc[]`/`Brief` → `Content` (`body` = markdown carrying image refs, `metadata.images[]` = generated paths). No new plugin kind, no new CLI surface, no ADR needed; workflows and skills both reach it through the existing executor, and it lands inside the repo's lint/test/coverage gate. Rejected: a `kk image` subcommand family (breaks the thin-CLI invariant in `docs/design/kk-cli-surface.md`) and skill-bundled bun scripts (invisible to workflows, outside the gate). — operator, 2026-09-09.
- **Preset model = `format × style`, two orthogonal axes.** `format` owns the job (aspect ratio, prompt skeleton, required variables, output naming, image count); `style` owns the look (palette, rendering, typography, negative hints). One slash-command interface serves every job: `--format cover --style editorial`. Replaces wt's ambiguous `template` naming; rejected baoyu's finer `type × palette × rendering` split as more concepts and more authoring than v1 earns. — operator, 2026-09-09.
- **v1 formats = `free`, `cover`, `illustration`.** Straight port of the three `wt` jobs plus the slash command. `xhs-card`, `infographic`, `comic`, `diagram` are deliberately deferred and must land later as *preset files only* — if they need engine changes, the format axis failed. — operator, 2026-09-09.
- **Providers = baoyu's full matrix.** All 12 adapters (google, openai, azure, openrouter, dashscope, zai, minimax, replicate, jimeng, seedream, agnes, codex-cli — the complete set; the earlier count of 13 was wrong, corrected against `vendors/baoyu-skills/skills/baoyu-image-gen/scripts/providers/` on 2026-09-09) behind one registry, not a 3-provider subset. This is the single largest chunk of the port and carries the 90%-coverage obligation for every adapter. — operator, 2026-09-09.
- **Style/format config generation from reference images is in scope for v1** — required capability, not a stretch goal (operator's stated requirement). *How* is ticketed, not decided.

### Not yet specified

- **Post-v1 formats as pure preset additions** — xhs-card is a *series* (2–10 cards with a swipe flow and outline strategy) and infographic needs structured-content extraction; both may demand engine seams (multi-image jobs, analysis artifacts) that v1's single-image path does not have. Revisit once the format schema exists.
- **Batch and concurrency policy** — baoyu carries per-provider concurrency caps and start-interval gaps (`BAOYU_IMAGE_GEN_<PROVIDER>_CONCURRENCY` etc.). Whether kk needs any of that, and where it would live (plugin option vs kk config), is unclear until the provider port is inventoried.
- **Image post-processing** — compression, @2x rasterisation, SVG→PNG (baoyu ships `baoyu-compress-image` and an SVG-based `baoyu-diagram`). Possibly a separate concern from generation entirely.
- **Asset lifecycle** — how a generated image survives a pipeline run and how publish plugins (`wechatmp`, `xhs`, `emdash`) consume a cover produced upstream. Touches the fan-in/fan-out spec. *(Premise corrected 2026-09-09: images do **not** land under `works_dir` — `works_dir` is expanded only by shell workflow nodes and is unreadable from any TypeScript in this repo (`grep -rn works_dir --include='*.ts'` → nothing). 0104 freezes artefacts as siblings of `--out`, matching `voice-gen`. What remains open is only the downstream half.)*
- **Cost and quota guardrails** across a 12-provider matrix — related to the confirmation open question but broader (per-run budget, dry-run prompt preview, spend logging).
- **Retirement of the `wt` image skills** — whether `cc-agents`' `wt` plugin keeps them, deprecates them, or points at `kk`. Out of this repo's tree but part of "migrate".
- **Localization** — baoyu detects source language and handles CJK text rendered inside images; `wt` does not. Relevant to `cover` (titles) and any future card format.

### Out of scope

- Renaming or repositioning knowledge-kit (settled in ADR-007 / feature J).
- Image upload, embedding, or platform-specific asset handling inside publish plugins — owned by `plugins/publishings/*`.
- Video and audio generation (audio is `voice-gen` / feature F7).
- Modifying the `cc-agents` `wt` plugin itself; it is read here as source material only.
- xhs-card, infographic, comic, and diagram formats — deferred by the v1-scope decision, to land later as preset additions.

- **Preference loading = `config.yaml` only, no `EXTEND.md`; chain is arguments > env > `$KK_CONFIG` `image:` > compiled defaults.** Resolves the map's open question (0106, closed Q&A): baoyu ranks `EXTEND.md` above env vars while kk ranks env above the config file — shipping both would give one product two contradictory precedence rules over the same keys. Non-blocking load with a one-line notice; credentials are outside the chain and never enter a job file. — operator, 2026-09-09.
