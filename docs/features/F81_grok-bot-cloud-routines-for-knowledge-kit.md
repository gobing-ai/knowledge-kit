# F81: Grok Bot cloud routines for knowledge-kit

## Goal

Let knowledge-kit run its scheduled work as Grok Bot routines in the cloud (laptop closed) and ship only runnable kk skills to a Bot, while keeping ADR-022 live-send consent and explicit missing/stale-data policies.

Depends on the superskill feature "Grok Bot plugin-native distribution and host probe" for the `requires:` contract and probe receipt. Evidence: routines are created by chat, run on schedules (≥5 min apart, 200 runs/hour/routine, 300/hour total) or webhook triggers (https://docs.x.ai/grok-bot/skills-routines-and-automations); `kk schedule render` currently supports only `launchd` and `cron` (`apps/cli/src/commands/schedule.ts:8`).

## Scope

- Annotate kk skills/commands with `requires:` per the superskill contract.
- `kk schedule render <wf> --platform grok-bot`: emits the routine instruction text (owning Bot, schedule + timezone, inputs, expected result, approval boundary, missing/stale-data policy) and an optional webhook trigger recipe; live channels still require the explicit ADR-022 consent token; rate-limit and min-interval validation.
- Decision recorded first: store locality (cloud routine prepares/drafts against a synced input vs. moving the kk store to the Bot computer).

**Out of scope:** creating routines programmatically (no documented API), moving the kk store without an explicit decision, new dependencies.
