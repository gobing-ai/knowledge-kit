# P: Workflow folder fallback and per-workflow workspace defaults

## Goal

Make `/kk:workflow-run` (and the kk-workflow-run skill) resolve workflow YAML and workspace folders
robustly with zero configuration: `workflows_dir` falls back to bun/npm global-install locations
when the config value is empty or unreadable, and every workflow gets a uniform default workspace
`$works_dir/<workflow-name>/<run-id>` with single-file steps flattened to `<step>-<name>` at the
work_dir root. Existing `.works` contents are never migrated.

## Scope

- In: `plugins/kk/commands/workflow-run.md` resolution chain + per-profile work_dir defaults;
  `plugins/kk/workflows/kk-itc.yaml`, `kk-solo-podcast.yaml`, `kk-daily-ai-voice.yaml` single-file-step
  flattening; `docs/04_DESIGN.md`, `plugins/kk/config.example.yaml`, `docs/help/*.md`;
  `apps/cli/tests/workflow-run-command.test.ts`, `kk-solo-podcast-workflow.test.ts`.
- Out: TS/CLI changes (no TS reads these keys); kk-storm-research.yaml (already flat);
  migration of existing `.works` contents; new resolver script or CLI noun (rejected at idea-eval).
