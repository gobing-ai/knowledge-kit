# P: Workflow folder fallback and per-workflow workspace defaults

## Goal

Make `/kk:workflow-run` (and the kk-workflow-run skill) resolve workflow YAML and workspace folders
robustly with zero configuration: `workflows_dir` falls back to bun/npm global-install locations
when the config value is empty or unreadable, and every workflow gets a uniform default workspace
`$works_dir/<workflow-name>/<run-id>` with single-file steps flattened to `<step>-<name>` at the
work_dir root. Existing `.works` contents are never migrated.

## Scope

- In: `plugins/kk/commands/workflow-run.md` resolution chain + per-profile work_dir defaults;
  `plugins/kk/workflows/kk-itc.yaml`, `kk-solo-podcast.yaml`, `kk-daily-ai-voice.yaml` single-file-step
  flattening; `docs/04_DESIGN.md`, `plugins/kk/config.example.yaml`, `docs/help/*.md`;
  `apps/cli/tests/workflow-run-command.test.ts`, `kk-solo-podcast-workflow.test.ts`.
- Out: TS/CLI changes (no TS reads these keys); kk-storm-research.yaml (already flat);
  migration of existing `.works` contents; new resolver script or CLI noun (rejected at idea-eval).

## Acceptance Criteria

```gherkin
Feature: Workflow folder fallback and per-workflow workspace defaults

  @core
  Scenario: R1 — Empty or missing workflows_dir falls back to global-install locations
    Given ~/.config/kk/config.yaml has workflows_dir absent, empty, or pointing nowhere readable
    And no user override and no KK_WORKFLOWS_SOURCE
    When /workflow-run resolves a workflow YAML
    Then it tries $(dirname $(bun pm bin -g))/install/global/node_modules/@gobing-ai/knowledge-kit/plugins/kk/workflows
    And then $(dirname $(npm root -g))/node_modules/@gobing-ai/knowledge-kit/plugins/kk/workflows
    And then the existing package-root walk and compiled default, first hit wins

  @edge
  Scenario: R2 — A corrupt config.yaml still fails loud
    Given ~/.config/kk/config.yaml exists but is not parseable YAML
    When /workflow-run runs
    Then it exits non-zero with the config error
    And no global-install fallback masks the failure

  @core
  Scenario: R3 — Each workflow defaults its work_dir under works_dir/<workflow-name>/
    Given works_dir resolves (flag > KK_WORKS_DIR > config > compiled default)
    And no explicit --dir / dir override
    When a profile's workspace is computed
    Then kk-storm-research uses $works_dir/kk-storm-research/<topic-id>
    And kk-itc uses $works_dir/kk-itc/<kebab>
    And kk-solo-podcast uses $works_dir/kk-solo-podcast/<date>
    And kk-daily-ai-voice uses $works_dir/kk-daily-ai-voice/<date>
    And an explicit --dir still wins over every default

  @core
  Scenario: R4 — kk-itc no longer writes into the caller's cwd
    Given no --dir for the kk-itc profile
    When the workspace is computed from any cwd
    Then the work_dir is under works_dir, never ./<kebab>

  @core
  Scenario: R5 — Single-file steps are flattened to <step>-<name> at the work_dir root
    Given a workflow step that emits exactly one file
    When the workflow writes it
    Then the file lands at <work_dir>/<step>-<name> with no single-file stage directory
    And steps emitting multiple files keep their stage directory

  @scope
  Scenario: R6 — Existing .works contents are never migrated
    Given leftover directories from earlier layouts under works_dir
    When any run completes
    Then those directories are left byte-identical
    And new runs write only to the new per-workflow locations

  @docs
  Scenario: R7 — Docs and content-asserting tests land in the same change
    When the feature ships
    Then docs/04_DESIGN.md (config table, per-profile defaults) and plugins/kk/config.example.yaml and the help docs state the new resolution chain and per-workflow defaults
    And apps/cli/tests/workflow-run-command.test.ts and kk-solo-podcast-workflow.test.ts assert the new contract
```
