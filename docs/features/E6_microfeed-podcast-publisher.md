# E6: microfeed podcast publisher

## Goal

Deploy a self-hosted microfeed instance on Cloudflare (operator-run via
`npx @microfeed/cli manage`) and ship a `podcast-pub` publish plugin that
publishes podcast episodes — audio media plus item metadata — to that
instance over its Bearer-authenticated `/api/v1/` REST API, with thin
management operations (list/get/update/delete items). The plugin completes
kk's audio half of the ingest → create → publish loop and unblocks the future
news→podcast automation workflow without building it.

## Scope

**In scope:**

- Operator-executed microfeed deployment to Cloudflare Workers (`wrangler`
  already authenticated) with verification: instance URL reachable, public
  JSON Feed returns 200, API access enabled, named write API key created.
- New publish plugin `plugins/publishings/podcast-pub/` (`kind: publish`,
  `file-cli` transport per `docs/design/publish-plugin-specification.md`):
  media upload via the microfeed prepare-upload flow and episode item
  create/publish, plus simple management operations (list/get/update/delete
  items) over `/api/v1/` with Bearer auth.
- Plugin configuration under `plugins.publishings.podcast-pub.env` in
  `~/.config/kk/config.yaml`: `MICROFEED_BASE_URL` (workers.dev URL now,
  custom domain after manual bind — config edit only) and
  `MICROFEED_API_KEY`.
- Offline tests via the publish-harness `FakeFileCliTransport` precedent; a
  gated live verification against the deployed instance.
- Design satellite `docs/design/` entry for podcast-pub per the T3 surface
  rule.

**Out of scope:**

- The chained AI/tech-news → podcast automation workflow (future feature;
  this feature only makes it possible).
- Custom domain binding (operator does it manually after deploy).
- Changes to kk-core schemas, the executor, or existing publish plugins.
- Browser-transport publishing; microfeed dashboard automation; webhook
  integrations.

  Scenario: R3 — podcast-pub publishes a podcast episode with audio to microfeed
    Given podcast-pub is configured with a valid MICROFEED_BASE_URL and MICROFEED_API_KEY
    When the plugin receives Content carrying episode metadata and an audio media reference
    Then it uploads the audio and creates the feed item via the microfeed /api/v1/ REST API
    And writes a Result JSON with ok true, target "podcast-pub", and the published item URL

  @core
  Scenario: R4 — podcast-pub provides simple management operations over the REST API
    Given podcast-pub is configured with valid credentials
    When a list, get, update, or delete item operation is invoked
    Then the corresponding /api/v1/ item endpoint is called and the outcome is reported as a Result JSON

  @core
  Scenario: R5 — podcast-pub passes offline contract tests without a live instance
    Given the publish-harness fake transport fixtures
    When the podcast-pub test suite runs
    Then publish and management behavior is verified with no network access to a real microfeed instance

  @edge
  Scenario: R6 — podcast-pub fails loudly with a diagnostic on API errors
    Given podcast-pub is configured with credentials
    When the microfeed API answers with an authentication or transport error
    Then the plugin writes a Result JSON with ok false and a diagnostic error, logs to stderr, and exits 1

  @edge
  Scenario: R7 — podcast-pub rejects invalid Content input before any network call
    Given Content missing required episode metadata or the audio media reference
    When the plugin is invoked
    Then it writes a Result JSON with ok false and a validation error and exits 1
