# G85: Daily AI Voice digest push notification

## Goal

Push the Daily AI Voice day digest to the operator outside the Board, once after generation and once after each publish window settles, through an off-by-default webhook whose URL never enters the repo, without a failed push ever failing the run.

## Scope

**In scope**

- `kk news digest --run-date <day> --push [--trigger generate|<window>] [--dry-run]`. It sends the same `DailyDigest` that G83's `kk news digest` renders (task 0439). The body is the markdown digest, with status, attention count and a Board deep link up front.
- One transport: an HTTPS webhook `POST`. The config key `notify.digest` in `~/.config/kk/config.yaml` (honours `KK_CONFIG`) has these fields:
  - `enabled` (default `false`);
  - `url_env`, the name of the environment variable that holds the URL, so the URL itself is never stored in config or the repo;
  - `body: markdown|json`;
  - `min_status`, so the push only goes out at or above `ok|attention|failed`.
  This covers ntfy, Slack-compatible and Telegram-bot style endpoints without a new dependency.
- At-most-once per trigger: a `<day>/notify-receipt.<trigger>.json` receipt records ts, status, http code and the body's sha256. A re-run with an unchanged digest does not push again. A changed digest pushes again and says so.
- Workflow wiring:
  - a final non-failing node in `kk-news-generate` after `freeze`;
  - a final non-failing step in `kk-publish` after the window report.
  Neither can change the run's outcome.
- `--dry-run` prints the exact body and target host, with the URL redacted, and sends nothing.

**Out of scope**

- Email/SMTP, SMS, the macOS notification centre and other transports. Add them when the webhook proves insufficient.
- Interactive replies or acknowledging from the notification.
- Per-target or per-attention-item pushes, and digests spanning several days.
- Storing any credential in the repo or in `config.yaml`.

```gherkin
Feature: Daily AI Voice digest push notification

  @core
  Scenario: R1 — The digest is pushed to the configured webhook
    # covers: I16
    Given notify.digest.enabled is true and the environment variable named by notify.digest.url_env holds an HTTPS URL
    When the operator runs kk news digest --run-date 20261125 --push --trigger generate
    Then one POST carrying the same status, attention items and window results as kk news digest --run-date 20261125 reaches that URL
    And a receipt notify-receipt.generate.json records the time, digest status, HTTP code and body sha256

  @core
  Scenario: R2 — Pushing is off by default and keeps the URL out of config and the repo
    # covers: I16
    Given notify.digest is absent or enabled is false, or the named environment variable is unset
    When the operator runs kk news digest --run-date 20261125 --push
    Then nothing is sent, the command explains which setting is missing and exits nonzero
    And no URL or token value appears in config.yaml, the receipt, stdout or the repository

  @core
  Scenario: R3 — A failed push never fails the run
    # covers: I16
    Given the webhook returns an error or times out
    When the push node runs at the end of kk-news-generate or a kk-publish window
    Then the workflow run keeps the outcome it had before the push node
    And the receipt and the run log record the failure with its HTTP code or error

  @core
  Scenario: R4 — Each trigger pushes at most once per unchanged digest
    # covers: I16
    Given a receipt for trigger cn-peak already records the current digest sha256
    When the cn-peak window is re-run and the push runs again
    Then no second POST is sent and the command reports the earlier receipt
    And a changed digest is pushed again and marked as an update

  @core
  Scenario: R5 — The push is wired after generation and after each publish window
    # covers: I16
    Given notify.digest is enabled
    When a kk-news-generate run freezes its bundle and when a kk-publish window writes its report
    Then the push runs with trigger generate and with the window name respectively

  @edge
  Scenario: R6 — A dry run shows the exact body without sending
    # covers: I16
    Given notify.digest is enabled
    When the operator runs kk news digest --run-date 20261125 --push --dry-run
    Then the body and the target host are printed with the URL redacted and nothing is sent or recorded
```
