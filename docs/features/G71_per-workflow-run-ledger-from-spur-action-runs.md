# G71: Per-workflow run ledger from spur action_runs

## Goal

Give every kk workflow an append-only `.works/<workflow>/ledger.md` with one section per run — per-step status, duration, tokens (or `unknown`) and result — sourced from spur's own action_runs so time and cost are visible without reading traces.

## Scope

- In: `kk ledger append|sync` rendering from `spur workflow trace --json`; idempotency by run id; honest `unknown` token cells; wiring into kk-collect (G31) and voice2 (G11) is done by those features.
- Out: token estimation; dashboards; retention of ledger files.

## Acceptance Criteria

```gherkin
Feature: Per-workflow run ledger from spur action_runs

@core
Scenario: R1 — Each workflow run appends a summary row block to its ledger
  # covers: I15, I16
  Given a completed kk-collect or voice2 run
  When kk ledger append --run <run-id> runs as the final node
  Then .works/<workflow-name>/ledger.md gains one run section with a per-step table of step, status, duration, tokens, and result
  And durations come from spur action_runs, not wall-clock guesses


@edge
Scenario: R2 — Unreported token usage renders as unknown, never estimated
  # covers: I16
  Given an agent step whose trace event carries no exact cost totals
  When the ledger row for that step is rendered
  Then its tokens cell reads unknown even when an estimated cost exists
  And the run total reports the count of steps with unknown usage
```
