# M: kk-user-config-roots

## Goal

Conform all kk user-level roots to `~/.config/kk/`: image-preset user root (`presets.ts`), user plugin-discovery root (`registry.ts`), and every living doc. Presets keep resolving in place from the installed package; user fine-tuning stays single-file shadowing into the (lazily created) user root.

## Scope

- In:
  - `plugins/generations/image-gen/src/presets.ts` user root `~/.kk/image-presets` → `~/.config/kk/image-presets`
  - `packages/kk-core/src/registry.ts` user root `~/.kk/plugins` → `~/.config/kk/plugins`
  - ADR-012 dated amendment (user roots under XDG-conforming `~/.config/kk/`; presets SSOT stays with the product plugin; no bulk seeding)
  - Living docs: docs/03_ARCHITECTURE.md, docs/04_DESIGN.md, docs/design/multi-root-plugin-discovery.md, plugins/kk/skills/image-authoring/SKILL.md, references/style-extraction.md, references/migrating-from-wt.md (path mentions only)
  - Migrate local `~/.kk/image-presets` content to `~/.config/kk/image-presets` (operator machine), dropping byte-identical-to-builtin duplicates
- Out:
  - Renaming project-level roots (`<KNOWLEDGE_KIT_PROJECT_ROOT>/.kk/image-presets`, `<cwd>/plugins`) or changing root priority order
  - A backward-compat fallback that also reads `~/.kk` (clean cutover)
  - Moving the presets SSOT or bulk-seeding the user root (rejected 2026-09-10, see Notes)
  - Historical records: done task files (0102/0105/0106), feature B7, docs/plans/, `.spur/memory/` keep their `~/.kk` mentions
  - config.example.yaml — verified zero path mentions; no edit
