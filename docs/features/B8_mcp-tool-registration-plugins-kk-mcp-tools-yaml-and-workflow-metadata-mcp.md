# B8: MCP tool registration (plugins/kk/mcp-tools.yaml and workflow metadata.mcp)

## Goal

Expose knowledge-kit's read-only CLI capabilities and three safe workflows to MCP hosts as `kk_*` tools through Spur's embedded MCP server (spur-new Task 1447, landed in `spur` 0.4.49). A coding agent, or the Spur gateway root `/mcp`, can then query plugin health, store yield and the wiki vault, and launch research, SEO and collection runs, without shelling out. The read-only and allowlist boundary is declared in repo-local files, and a test fails when those files drift from the CLI and workflow vars they wrap.

## Scope

- **In:**
  - `plugins/kk/mcp-tools.yaml`: four read-only tools (`plugin_status`, `store_stats`, `wiki_query`, `wiki_context`) in the strict 1447 shape.
  - `metadata.mcp` opt-ins with typed `params` allowlists on `kk-storm-research`, `kk-smart-seo` and `kk-collect`.
  - `apps/cli/tests/mcp-tools-manifest.e2e.test.ts`.
  - The live E2E on the project and gateway `/mcp`.
- **Out:**
  - Mutating `kk` verbs as manifest tools.
  - `kk-publish` (external publishing needs operator authorization).
  - HITL-paused workflows (`kk-solo-podcast`, `kk-article-generate`), and the daily, music and example workflows.
  - Renaming workflows to drop the `kk_kk_` stutter.
  - Any edit in `spur-new`.
  - A kk-side copy of the manifest JSON Schema.
  - The `kk wiki` missing-vault `ENOENT` crash (separate task).
