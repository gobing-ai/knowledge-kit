# D7: image-gen pre-spend illustration anchor validation

## Goal

An `image-gen` illustration job with an invalid anchor plan never reaches provider selection, the dry-run preview, or a paid call. The plan is invalid when an anchor is missing, does not occur exactly once, or overlaps another anchor. The 0107 contract ("validates anchor occurs exactly once BEFORE spending image bytes") becomes true in the code, and the `kk:image-authoring` preview → confirm → paid flow never asks the operator to approve a doomed run.

## Scope

**In scope**

- Pre-provider validation of the illustration anchor plan in `processGeneratorIO` (`plugins/generations/image-gen/src/index.ts`), on both the dry-run and the paid branch: every prompt has an anchor, each anchor occurs exactly once in the original body, and anchor occurrences are pairwise disjoint.
- Existing anchor error messages are kept verbatim, plus one new overlap message.
- Regression tests: no provider selection, no `generate`, and no files left behind for bad plans. Valid plans produce byte-identical output.

**Out of scope**

- Single-pass insertion over the original body (would remove the alt-text/path residual). This is a later increment if that residual ever occurs.
- Anchor selection quality. That is `kk:image-authoring` model work (0106).
- Runtime provider fallback (D6). D7 only guarantees that anchor errors are raised before spend, which D6's loop (0166) relies on.
