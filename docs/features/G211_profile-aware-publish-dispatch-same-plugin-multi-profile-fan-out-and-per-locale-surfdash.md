# G211: Profile-aware publish dispatch: same-plugin multi-profile fan-out and per-locale surfdash

## Goal

## Scope

Dogfood of `plugins/kk/workflows/kk-itc.yaml` (2026-10-16/17, run kk-itc-20261016T224508-18167) proved the publish dispatch layer cannot carry the same plugin more than once:

- `apps/cli/src/itc-publish.ts` keys per-target payloads (`content.<plugin>.json`), receipts (`receipts/<plugin>.json`) and fan-out aggregates (`fanout-result.<plugin>.json`) by **plugin name only** — a second profile of the same plugin overwrites/reuses the first target's artifacts (the `exists` guard then silently reuses the first result).
- `kk executor fan-out --target <plugin>` never passes the profile to the plugin invoke (`apps/cli/src/fanout.ts`); profile choice exists only as metadata switches baked into the payload.
- Consequence: per-locale surfdash (`article-zh`/`article-ja`/`article-en` profiles, locale fixed per profile) is not dispatchable; `surfdash-pub` `publish` reads locale only from `SURFDASH_LOCALE` (`plugins/publishings/surfdash-pub/src/index.ts`), so N targets would all write the same locale.

Scope: key payloads/receipts/aggregates by plugin+profile; thread the profile through fan-out to the plugin invoke; let surfdash-pub resolve locale from content metadata (fallback env). Unblocks the itc-main preset carrying surfdash zh/ja/en in one run; until then the zh-only + `scaffold-locale` follow-up is the supported path.
