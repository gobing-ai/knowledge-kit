# F614: Daily cover: news-driven image with a fixed visual style

## Goal

Make each daily `kk-daily-ai-voice` cover image show that day's news, while the visual style stays the same across episodes. This is the image counterpart of F613: the style is held by checked-in image presets (format + style) and a pinned provider/model. Per run, an agent writes only a short visual `subject` from the lead plan item — the same `2-plan/<date>_03_plan_plan.json` the script and show notes use.

## Scope

**In scope**

- Shipped image-gen presets `formats/daily-news-cover.yaml` and `styles/daily-news.yaml`. Composition, palette, visual approach and negatives are fixed in the files; `subject` is the only per-run variable.
- The `cover` state becomes: agent writes a cover brief `{subject}` from the lead plan item (`onError: continue`), then a deterministic `kk stage daily-cover` builds the image-gen `--in` envelope and runs `kk executor run image-gen`.
- Pinned `cover_provider` / `cover_model` workflow vars (default `minimax` / `image-01`, the provider the 2026-09-24 run used).
- Fallback: a missing or invalid brief uses a fixed default subject and logs the reason; the cover still generates in the same style.
- `daily-cover-normalize` reads the artifact path from `2-cover/content.json`, not a hard-coded `content-cover-01.*` name.

**Out of scope**

- Changing the 21:9 aspect ratio, cover consumers (publish-prep, surfdash patch, podcast), or `cover_enabled` semantics.
- Reference-image style anchoring (provider `referenceImages`) and seeds — follow-up if presets alone drift.
- Text or title rendered inside the image (banned; titles live in the post/podcast metadata).
- Changing the `kk:image-authoring` skill or the generic `cover` / `vibrant` presets.

```gherkin
    When the workflow reaches the cover state

    And its prompt stays within 1000 characters per ADR-115
    And it writes 2-cover/<run_date>_07_cover-brief.json holding one subject that depicts plan item 1

  @core
  Scenario: R3 — The cover image is generated deterministically from the brief
    Given a valid cover brief
    When kk stage daily-cover runs
    Then it runs image-gen with format daily-news-cover, style daily-news, the pinned cover_provider and cover_model, maxImages 1, and vars.subject from the brief
    And no other template variable is passed
    And the normalized cover lands at 2-cover/<run_date>_07_cover_cover.png

  @core
  Scenario: R4 — A missing or invalid brief falls back to the default subject
    Given the cover brief is absent, not JSON, has no subject, or its subject exceeds the cap
    When kk stage daily-cover runs
    Then image-gen runs with the format's default subject and the same format, style, provider and model
    And the stage logs a warning naming the fallback reason
```
