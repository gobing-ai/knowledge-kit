# B7: Judge plugin kind

## Goal
LLM-as-judge as a fourth plugin kind (`kind: judge`, `Content → Verdict`, gate-only semantics) — first-class, discoverable via the registry (`kk plugins list --kind judge`), reusable across pipelines (task 0034). Extends B1 registry + B2 contracts + B4 CLI; the ADR-007 amendment recording the kind is task 0036. Implementation graduates here once map J closes.
## Scope
- In: `judge` kind in PLUGIN_KINDS / CONTRACTS; VerdictSchema; `kk invoke` judge support; workflow gating pattern (shell guard + jq verdict check).
- Out: bounded regenerate-retry loops (map-J fog); verdict-feedback payloads.
## Acceptance Criteria
```gherkin
Feature: Judge plugin kind

  Scenario: A judge is discoverable as its own kind
    Given a plugin directory whose manifest declares kind "judge"
    When `kk plugins list --kind judge` runs
    Then the plugin is listed under the judge kind

  Scenario: A judge emits a schema-valid verdict
    Given a judge plugin and a Content input file
    When `kk invoke <judge> --in content.json --out verdict.json` runs
    Then verdict.json validates against VerdictSchema
      And the verdict field is one of PASS, FAIL or NEEDS_REVISION

  Scenario: A rejecting verdict gates a workflow transition
    Given a spur workflow with a judge step preceding publish
    When the judge returns a FAIL verdict
    Then the publish transition does not fire
```
