### Findings

- **`type: parallel` has no executor in `@gobing-ai/ts-dual-workflow-engine@0.4.14`.** The token
  appears only in `src/types.ts:77`, `src/schema.ts:100` and
  `schemas/transition-flow-workflow.schema.json:38`. Stronger still: **no executor reads `node.type`
  at all**, and `src/service.ts:24` documents deliberate per-run serialization. The engine is
  sequential by design, not missing a feature. This is the evidence behind the kk-owned-fan-out call.
- **`spur task verdict` parses only markdown tables** (`| Req | Status | Evidence |`,
  `| AC | Status | Evidence Type | Evidence |`). Prose traceability yields zero parsed requirements
  and therefore `UNKNOWN` — the root cause of 0032's original forced-done. An AC marked MET with
  `static-ref` evidence is downgraded to PARTIAL unless its id carries `[docs-only]` / `[non-behavior]`
  / `[advisory]`.
- **`spur feature update --field name` rewrites frontmatter only** — not the `# H1` and not the
  filename slug. A renamed feature needs a manual H1 edit plus `git mv`; there is no CLI-gated repair.
- **The drift was one of centre of gravity, not missing scope.** `ADR-006` already described
  ingest → generate → publish. What genuinely changed: creation-without-ingestion, and publishing
  promoted out of deferral.
