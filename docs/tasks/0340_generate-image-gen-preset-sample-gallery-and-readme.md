## 0340. Generate image-gen preset sample gallery and README

### Background

Implements: R1 — The plugin ships one README indexing every shipped preset; R2 — Every format and style pair has a sample image on disk; R3 — The README grid embeds every sample under its format and style; R4 — The gallery is regenerated by one resumable script; R5 — A failed provider call does not lose finished samples.

The operator's ask of record is the idea input persisted by the idea pipeline: a README for `plugins/generations/image-gen` indexing all format × style combinations, with samples generated into `plugins/generations/image-gen/assets/sample`.

**Premises (verified against the tree 2026-11-04):**

- Any style composes with any format — `composePrompt` joins body, format keywords and style modifiers with no pairing check (`plugins/generations/image-gen/src/presets.ts:259`).
- The spec's `job` must equal the format's `job` (`plugins/generations/image-gen/src/index.ts:107`): `cover` and `daily-news-cover` → `cover`, `free` and `xhs-card` → `free`, `illustration` → `illustration`.
- The illustration job needs `metadata.positions` anchors present once in the doc body (`plugins/generations/image-gen/src/index.ts:158`), so the sample envelope carries a one-anchor body.
- The free job feeds the doc body into the `subject` var unless `vars.subject` is set (`plugins/generations/image-gen/src/index.ts:149`), so samples pin `vars.subject` for comparability.
- The established invocation is `kk executor run image-gen --in <envelope> --out <content.json>` with `metadata.imageGen` `{job, format, style, vars, maxImages: 1}` (`plugins/kk/scripts/daily-stages.ts:585-601`).

### Requirements

### Design

- Approach: `scripts/gen-samples.ts` loads shipped presets via the existing `src/presets.ts` loader (builtin root only), and for each pair runs `kk executor run image-gen` with a `{job, format, style, provider, maxImages: 1}` envelope, copying the produced artifact to `assets/sample/<format>__<style>.jpg`; then renders README from preset metadata. Reason: reuses the real execution path, so samples reflect what users get.
- Rejected: calling provider adapters directly (bypasses prompt composition and the xhs-card compose step); hand-written README (drifts from presets).
- Invariants: no preset or runtime code change; existing samples are never overwritten unless `--force`; README is fully derived from preset files + sample presence.
- Key signatures: `bun scripts/gen-samples.ts [--provider <p>] [--model <m>] [--force] [--readme-only]`.

### Solution

- `plugins/generations/image-gen/scripts/gen-samples.ts:57` (envelope), `plugins/generations/image-gen/scripts/gen-samples.ts:122` (resumable render loop), `plugins/generations/image-gen/scripts/gen-samples.ts:149` (README) — loads only the builtin `presets/{formats,styles}` root (Bun.YAML + exported `FormatPresetSchema`/`StylePresetSchema`), builds one Doc envelope per pair with fixed per-job inputs (cover vars; illustration anchor in body + `metadata.positions`; free/xhs-card `vars.subject`, xhs-card headline/points), runs the real `kk executor run image-gen` (default `minimax`/`image-01`, `--provider`/`--model` override) with concurrency 3, and downscales each result via `sips` to a 640px JPEG at `assets/sample/<format>__<style>.jpg`. Existing samples are skipped unless `--force` (R4/R5 resumability); failed pairs are named and the script exits 1; `--readme-only` rebuilds the index alone.
- `plugins/generations/image-gen/README.md` — generated index: formats table (job, aspect, size, default style), styles table, and a per-format 3-column gallery with the default style marked ★ (R1/R3).
- `plugins/generations/image-gen/assets/sample/` — 60 samples (5 formats × 12 styles), 3.1 MB total (R2).
- Deviation: samples are `.jpg` thumbnails, not `.png` — they ship in the npm tarball (`scripts/bundle-plugins.ts` does not exclude `assets/`), so full-size PNGs (~300 KB+ each) were rejected; K1 AC and task R2/Design reworded via CLI.
- Known ceiling: thumbnailing depends on macOS `sips` (`ponytail:` comment in the script).
