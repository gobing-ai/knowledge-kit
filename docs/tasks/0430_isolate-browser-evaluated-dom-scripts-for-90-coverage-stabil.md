## 0430. Isolate browser-evaluated DOM scripts for 90% coverage stability and automate worktree plugin bundling

### Background

Publish adapters — especially `plugins/publishings/wechatmp-pub/src/flow.ts` (90.5% fn / 91.5% ln in `.coverage/lcov.info`) and sibling adapters (`xhs-pub/src/flow.ts` 90.7% fn, `bilibili-pub/src/flow.ts` 90.8% fn, `shipinhao-pub/src/audio-flow.ts` 90.9% fn, `wechatmp-pub/src/page.ts` 91.3% fn) — sit right at the 90% per-file function/line coverage floor enforced by `bunfig.toml`, causing fragile gate failures whenever a branch is added or a subprocess fixture runner changes. #### Q&A entry — 2026-11-24T23:46:24.267Z

- **Why NOT ignore production `src/` DOM-script modules in `bunfig.toml`:** Premises audit proved zero `page.evaluate((...) => ...)` JS function callbacks exist in `plugins/`; all `page.evaluate(...)` calls already pass string expressions. Ignoring production `src/` files would weaken the 90% gate without fixing the real gap (`wechatmp-pub/src/flow.ts:3329-3444` Node/Bun logic).
- **Why keep `launch.ts` `runPreflight` read-only:** `apps/cli/tests/launch.test.ts:335-339` pins the exit-5 refusal on divergence, and outside a checkout `install` is a global package directory that `bundle-plugins.ts` cannot rebuild. Refreshing `apps/cli/plugins` in `prepare` + `.lefthook.yml` solves worktree staleness at the write/checkout boundary instead.
- **Why `--if-stale` instead of unconditional `bundle-plugins.ts` in hooks:** Full `bundlePlugins()` runs `Bun.build` across all product plugins (~2-4 s). Comparing `plugins/kk/{scripts,workflows}` + plugin manifests/entries against `apps/cli/plugins` (or checking missing target) skips clean trees in <50 ms so `post-checkout` / `pre-commit` stay fast.

### Design

#### WHAT / WHY / WHERE

1. **Coverage headroom & fixture-runner hygiene (R1):** Stabilize the 90%/90% per-file coverage floor on publish adapters by adding in-process unit tests for the uncovered Node/Bun branches in `plugins/publishings/wechatmp-pub/src/flow.ts` (chiefly `L3329-3444` audio cover-chooser branch, currently 90.5% fn / 91.5% ln) and near-90% sibling adapters (`xhs-pub/src/flow.ts`, `bilibili-pub/src/flow.ts`, `shipinhao-pub/src/audio-flow.ts`, `wechatmp-pub/src/page.ts`), and replacing the 7 hand-listed `**/tests/fixtures/*-runner.ts` entries in `bunfig.toml:24-51` with a single `**/tests/fixtures/*-runner.ts` ignore pattern (covering all 11 subprocess-only runners including `wechatmp-dom-runner.ts`, `wechatmp-cgi-runner.ts`, `bot-record-runner.ts`, and `browser-anti-detection-runner.ts`).
2. **Automatic worktree plugin bundling (R2):** Add an idempotent `--if-stale` mode to `scripts/bundle-plugins.ts` and wire it into `package.json` `prepare` and `.lefthook.yml` (`pre-commit`, `post-checkout`, `post-merge`) so `apps/cli/plugins/` never drifts from `plugins/kk/{scripts,workflows}` in a worktree.

  - Replace the 7 individual `**/tests/fixtures/<name>-runner.ts` lines (`L24-51`) with `"**/tests/fixtures/*-runner.ts"` plus a concise comment explaining subprocess-only `spawnSync` fixture runners.
