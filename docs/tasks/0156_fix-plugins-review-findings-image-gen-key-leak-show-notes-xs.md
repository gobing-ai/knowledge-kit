#### Q&A entry — 2026-09-23T23:40:22.504Z

Triage decisions were made when the task was created (2026-09-23) and bind the implementer. Re-opening one needs an operator decision.

- **Q: Should #5 be fixed with one default timeout on `kk plugin invoke` instead of 42 per-fetch signals?** A: **No.** The single-invoke path (`apps/cli/src/invoke.ts:398`, sync `spawnPluginEntry`) could adopt `spawnPluginEntryAsync`'s `timeoutMs` (`:167-176,241-285`), but no whole-plugin default is correct. voice-gen legitimately runs for hours (a 140-min dogfood run, `voice-gen/src/index.ts` retry comments), fan-in already defaults to 30 min per source and needs a 45 min override for horizon (`docs/04_DESIGN.md:159-160`), and a whole-plugin kill loses completed work. Per-request timeouts bound the actual failure (a stalled socket) without capping legitimate long runs. An opt-in `--timeout` on `invoke` is a separate feature, if anyone asks.
- **Q: Why not wrap `options.fetch` once in image-gen instead of editing 26 call sites?** A: `google.ts:145` switches to the curl proxy path only when `options?.fetch === undefined`, so a global wrapper would silently disable the proxy workaround. Also, per-site `signal` keeps each call self-evidently bounded, and the AC5 static `rg` backstop can check that.

```ts

    const lines = markdown.split('\n');
    if (lines[0]?.trim() !== '---') return markdown;
    const close = lines.findIndex((l, i) => i > 0 && l.trim() === '---');
```

### Root Cause

All anchors are at `main@d4dd562d`. Every repro below was run during the review or during task creation (2026-09-23).

- **R1:** The curl branch was ported from upstream (`google.ts:144` comment, task 0115) with the key as a `-H` argv element. `execFileSync` builds its thrown `Error.message` as `Command failed: <file> <args…>` (Node `child_process` docs), and `-s` silences curl's stderr, so `details` falls back to `e.message`, which is the full argv, key included. `image-gen/src/index.ts:311` prints it (`image-gen failed: …`). Repro (review probe): a failing proxy produced `Command failed: curl -s … -H x-goog-api-key: SEKRET123 -d @-`. The key is also readable by any local user via `ps` for the duration of the call. The same applies to `user:pass@` in `HTTPS_PROXY`.
- **R2:** `renderTimelineHtml` (`show-notes.ts:105-130`) escapes the **value** of `sourceUri` but never checks its **scheme**, so `javascript:` survives HTML escaping intact. `DocSchema.sourceUri` is `z.string().optional()` (`packages/kk-core/src/schemas.ts:8`), and docs come from ingestion (web/RSS) and are therefore untrusted. Separately, `renderShowNotesHtml` (`:155-166`) trusts any text between the markers, but the input is `metadata.showNotes` **or `content.body`** (`map.ts:146-149`), both agent- or LLM-written. microfeed renders `content_html` unescaped (`{{{content_html}}}`), so both issues become stored XSS on the public podcast site. Repros: `sourceUri: 'javascript:alert(document.domain)'` produced a live `href`; `<!--kk:timeline-->\n<script>alert(1)</script>\n<!--/kk:timeline-->` passed through verbatim. The header comment (`:1-12`) claims "sanitize-by-construction", which the code does not deliver.
- **R3:** `normalizeLocaleFrontmatter` blanks lines to delete them (`lines[i] = ''`) and then removes the blanks with `lines.filter((line) => line !== '')` over the **whole document**, which also removes every legitimate empty line in frontmatter and body, including the trailing newline. `syncPost` (`:390-397`) writes the result back whenever it differs, so every `sync` corrupts the en/ja siblings: paragraphs merge in rendered markdown, and code blocks lose blank lines. No test covers the function. Repro: `'---\ndraft: true\n---\n\nPara one.\n\nPara two.\n'` → `'---\ndraft: false\n---\nPara one.\nPara two.'`.
- **R4:** `runDate` is taken verbatim from `metadata.runDate` (`:433`, any string) and joined into `postDir` (`:438`). `join` normalises `..`, so the post directory escapes the articles tree. Repro: the resolved path was `/root/tmp/evil-post`. `coverImage` is any existing path (`:444`), copied into a post that `pushPostGit` then publishes to a public git repo. The extension comes from `lastIndexOf('.')` on the **full path**, so `/a.b/cover` yields `.b/cover`. podcast-pub likewise treats every non-`http` `coverImage` as a local file (`map.ts:109-110`), reads it, uploads it, and sends the absolute `full_local_file_path` to the server (`index.ts:338-347`), with the MIME type always `image/png`. The metadata is written by an agent following `plugins/kk/skills/article-adapt/SKILL.md:33,46`, so a prompt-injected source document can steer it. Confidence: HIGH for the path escape; MEDIUM for the end-to-end exploit chain (it requires an injected agent to set those fields).
- **R5:** Plugins were written against `fetch` with no default timeout. Bun's `fetch`, like WHATWG fetch, has no overall request deadline unless a `signal` is passed (MDN `AbortSignal.timeout`). Only podcast-pub's microfeed client and surfdash's live-URL poll pass one. The workflow invokes plugins through the sync `spawnPluginEntry` (`invoke.ts:398`) with no timeout, so a stalled peer hangs the step until someone kills the run.
- **R6:** `dailyPatchSurfdash` wrote its own git sequence (`:1402-1407`) instead of mirroring `pushPostGit`. `git add content/posts/articles` stages every change under the tree, `git commit -m` commits the **whole index** (including anything the operator had staged), and `git push` pushes the current branch to its upstream, whatever that is.
- **R7:** When surfdash-pub was written, `JSON.parse`/`ContentSchema.parse` (`:555-556`) sat outside a `try`. The other publishers were built from a template that already had the "Invalid Content input" catch (`infoq-pub/src/index.ts:84-94`). With no `C2` shared runner, nothing enforced the spec §2.5 behavior across the 12 copies.
- **R8:** `presets.ts:269` hard-codes `':'`. This is the same defect class as `packages/kk-core/src/registry.ts:150`, which is fixed by task 0155 R6.
- **R9:** `wechatmp-pub` `escapeHtml` (`:34-36`) escapes `& < >` only, and the link regex (`:61`) interpolates the destination into `href="$2"`. So a `"` in the destination closes the attribute, and any scheme is emitted. Repros: `[y](a" onclick="z)` → `<a href="a" onclick="z">y</a>`; `[x](javascript:alert(1))` → a live `javascript:` href.
- **R10:** The `npx` invocation was ported from the `wt-publish-to-zenn` skill (`:24,144` comments), which assumed `zenn-cli` is installed in the repo. `npx <name>` without `--package` resolves the npm package **named** `zenn`, which was unpublished on 2021-04-20 (`npm view zenn` → E404 "Unpublished"). `--yes` suppresses the install prompt. The git steps (`:185-190`) copy the same unscoped `commit`/`push` pattern as R6. The URL (`:208`) omits the username segment. Verified 2026-09-23: `https://zenn.dev/articles/zenn-cli-guide` → HTTP 404, `https://zenn.dev/zenn/articles/zenn-cli-guide` → HTTP 200.
- **R11:** `upsertKey` builds `key: '<value>'` without YAML single-quote escaping (YAML 1.2 §7.3.2: `'` inside single quotes is written `''`). `String.prototype.replace` with a **string** replacement interprets `$&`, `$1` and `$$` (MDN "Specifying a string as the replacement"). The `m`-flag regex runs over the whole document, so a body line starting with `image:` or `og_image:` is rewritten instead of the frontmatter key.
